# Ensembl client coding standards

## Scope and rule levels

This is the citable source for standards findings in Ensembl client code review. It complements the architecture and command guidance in [`AGENTS.md`](AGENTS.md); it is not a complete repository manual.

- **Required standard**: an explicit project instruction or a rule enforced by repository configuration or checks. A diff can violate it.
- **Established convention**: a repeated, maintained local pattern. Deviations need context and may be justified.
- **Review heuristic**: a prompt for human judgement. It is not a breach by itself.

Review only rules relevant to the diff. Prefer the linked authority over this summary if the current checkout has changed.

## Repository structure and TypeScript

- **Required standard — repository imports and source files.** New source files must carry the Apache 2.0 header. Use configured aliases such as `src/*`, `config`, `static/*`, `stories/*`, `tests/*`, and `webpackDir/*` rather than long cross-project relative imports. Review new files for the header and changed imports for the established module boundary. Sources: [`AGENTS.md`](AGENTS.md), [`tsconfig.json`](tsconfig.json), [`src/store.ts`](src/store.ts).
- **Established convention — code ownership follows scope.** App-specific code stays under its app in `src/content/app/`; cross-app primitives and utilities live under `src/shared/`; server-only behaviour lives under `src/server/`. A diff should not move one-off feature logic into a shared abstraction without demonstrated reuse. Sources: [`AGENTS.md`](AGENTS.md), [`src/content/app/`](src/content/app/), [`src/shared/`](src/shared/), [`src/server/`](src/server/).
- **Review heuristic — follow the nearest maintained shape.** Check comparable source, call sites, and tests before introducing a second naming, export, event-handler, or file-splitting pattern. A local exception is acceptable when the surrounding pattern is inconsistent or unsuitable. Source: [`src/shared/components/`](src/shared/components/).

Formatting, unused-symbol diagnostics, equality checks, and other rules already decided completely by TypeScript, ESLint, Stylelint, Prettier, or pre-commit checks are not separate manual standards. Review the remaining design and boundary choices instead. Sources: [`eslint.config.js`](eslint.config.js), [`stylelint.config.mjs`](stylelint.config.mjs), [`tsconfig.json`](tsconfig.json), [`package.json`](package.json).

## React, shared components, accessibility, and CSS

- **Established convention — reuse by semantic fit.** Before adding UI markup or a primitive, check `src/shared/components/`, its call sites and tests, and matching Storybook examples. Prefer a fitting shared component, then composition, then a backward-compatible generally useful extension. Keep domain-specific UI feature-local; create a shared primitive only for demonstrated reuse. Review for copied primitives and abstractions created from a single use case. Sources: [`src/shared/components/button/Button.tsx`](src/shared/components/button/Button.tsx), [`stories/shared-components/button/Button.stories.tsx`](stories/shared-components/button/Button.stories.tsx), [`src/shared/components/`](src/shared/components/).
- **Required standard — CSS placement and load order.** Co-locate feature and component styles as CSS Modules. Do not add a global style for a local need, and do not reorder the global-style import ahead of hydration because it establishes CSS layer order. Review CSS changes for the correct scope and client-entry changes for preserved ordering. Sources: [`AGENTS.md`](AGENTS.md), [`src/initialiseClient.tsx`](src/initialiseClient.tsx), [`src/styles/globalStyles.ts`](src/styles/globalStyles.ts).
- **Established convention — use the design language before literals.** Reuse existing colour, type, spacing, shadow, and form tokens, plus supported component custom-property hooks, before adding equivalent values or copying private styles. Add a global token only for an intentional reusable primitive after checking existing consumers. Sources: [`src/styles/design-tokens.css`](src/styles/design-tokens.css), [`src/shared/components/button/Button.module.css`](src/shared/components/button/Button.module.css), [`stories/design-primitives/`](stories/design-primitives/).
- **Review heuristic — preserve interaction semantics.** Check native semantics, labels, keyboard and focus behaviour, disabled states, responsive behaviour, and the intended meaning of established variants when composing or extending UI. For example, primary and secondary buttons represent different user intentions. Sources: [`stories/shared-components/button/primaryButtonNotes.md`](stories/shared-components/button/primaryButtonNotes.md), [`stories/shared-components/button/secondaryButtonNotes.md`](stories/shared-components/button/secondaryButtonNotes.md), [`src/shared/components/button/Button.tsx`](src/shared/components/button/Button.tsx).

## Routes, SSR, hydration, and browser/server boundaries

- **Required standard — top-level routes have one source of truth.** Add or change top-level routes in `src/routes/routesConfig.tsx`; nested app routing remains app-local. Pages requiring data during server-side rendering export and register `serverFetch`. Review route diffs for both client and server matching and for the fallback route. Sources: [`AGENTS.md`](AGENTS.md), [`src/routes/routesConfig.tsx`](src/routes/routesConfig.tsx), [`src/server/routes/viewsRouter.tsx`](src/server/routes/viewsRouter.tsx).
- **Required standard — preserve the server/client rendering contract.** Changes to route fetching, page metadata, Redux preloaded state, transferred configuration, providers, or the HTML tree must remain compatible between server rendering and client hydration. Review loading and error paths as well as the successful path. Sources: [`src/server/routes/viewsRouter.tsx`](src/server/routes/viewsRouter.tsx), [`src/content/html/Html.tsx`](src/content/html/Html.tsx), [`src/initialiseClient.tsx`](src/initialiseClient.tsx), [`src/content/app/species/SpeciesPage.tsx`](src/content/app/species/SpeciesPage.tsx).
- **Established convention — make environment boundaries explicit.** Guard `window`, DOM, IndexedDB, and other browser-only APIs, or defer their work until the client has mounted. Resolve backend configuration through `config.ts` so browser proxy paths and server-side URLs remain distinct. Review shared imports for module-level browser access that can execute during SSR. Sources: [`src/shared/helpers/environment.ts`](src/shared/helpers/environment.ts), [`config.ts`](config.ts), [`src/index.ts`](src/index.ts).

## Redux, RTK Query, and asynchronous state

- **Required standard — use the typed store interface.** New or changed app code should use `useAppSelector`, `useAppDispatch`, `RootState`, `AppDispatch`, and `createAppAsyncThunk` from `src/store.ts` rather than introducing untyped React Redux hooks. Existing untyped call sites are not evidence for a new convention. Sources: [`AGENTS.md`](AGENTS.md), [`src/store.ts`](src/store.ts).
- **Required standard — inject feature API endpoints.** Define feature-specific REST and GraphQL endpoints by injecting them into the shared RTK Query slices; do not create competing central API clients for ordinary feature endpoints. Review endpoint ownership, exported hooks/endpoints, and registration of reducer and middleware when shared infrastructure changes. Sources: [`AGENTS.md`](AGENTS.md), [`src/shared/state/api-slices/restSlice.ts`](src/shared/state/api-slices/restSlice.ts), [`src/shared/state/api-slices/graphqlApiSlice.ts`](src/shared/state/api-slices/graphqlApiSlice.ts), [`src/shared/state/genome/genomeApiSlice.ts`](src/shared/state/genome/genomeApiSlice.ts).
- **Established convention — keep state ownership local.** App reducers, slices, epics, listeners, and API modules normally live with their owning app; genuinely cross-app state belongs under `src/shared/state/`. Review new root-level state for a clear ownership reason and ensure root reducer, epic, listener, and server-store implications are considered. Sources: [`src/root/rootReducer.ts`](src/root/rootReducer.ts), [`src/root/rootEpic.ts`](src/root/rootEpic.ts), [`src/server/serverSideReduxStore.ts`](src/server/serverSideReduxStore.ts).

## Testing and validation

- **Required standard — select the test environment by suffix.** Browser-dependent UI/component tests use `*.browser.test.ts(x)` and the browser Vitest configuration; pure logic and tests that do not require browser APIs use `*.test.ts(x)` and the Node configuration. Review the behaviour under test, not merely whether the file contains JSX. Sources: [`doc/testing.md`](doc/testing.md), [`vitest.config.mts`](vitest.config.mts), [`vitest.config.browser.mts`](vitest.config.browser.mts).
- **Established convention — extend the nearest useful seam.** Behaviour changes should receive focused coverage at the narrowest stable interface. Shared UI primitives may also need a maintained Storybook example, especially when semantics or supported variants change. Sources: [`src/shared/components/button/Button.test.tsx`](src/shared/components/button/Button.test.tsx), [`stories/shared-components/button/Button.stories.tsx`](stories/shared-components/button/Button.stories.tsx), [`doc/testing.md`](doc/testing.md).
- **Review heuristic — validate in proportion to risk.** Start with the narrowest relevant tests, then use type checking and applicable script/style linting for the touched areas. A build does not replace type checking. Sources: [`AGENTS.md`](AGENTS.md), [`package.json`](package.json).

## Documented exceptions to generic review heuristics

- **Established convention — shared is not automatically better.** Feature-local components and local design values are appropriate when the behaviour or presentation is domain-specific and no fitting shared primitive or token exists. Do not report duplication or a missed abstraction solely because a one-off implementation could be generalised. Sources: [`src/content/app/`](src/content/app/), [`src/shared/components/`](src/shared/components/), [`src/styles/design-tokens.css`](src/styles/design-tokens.css).
- **Established convention — client-only rendering can be intentional.** A guarded browser-only branch or rendering after mount can protect hydration and browser API boundaries. Review whether the guard is necessary and stable; do not label it a generic conditional-complexity smell without considering SSR. Sources: [`src/content/app/species/SpeciesPage.tsx`](src/content/app/species/SpeciesPage.tsx), [`src/shared/helpers/environment.ts`](src/shared/helpers/environment.ts).
- **Established convention — `any` is not automatically a standards violation.** The project is strict TypeScript but deliberately does not enforce `no-explicit-any`; review `any` when it hides an important domain or server/client boundary, not as a standalone breach. Sources: [`tsconfig.json`](tsconfig.json), [`eslint.config.js`](eslint.config.js), [`src/routes/routesConfig.tsx`](src/routes/routesConfig.tsx).
